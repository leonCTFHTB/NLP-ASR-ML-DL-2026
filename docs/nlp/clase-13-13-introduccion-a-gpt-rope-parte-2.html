11. Positional Encoding en Transformers

11.1. Equivariancia a la permutación en self-attention

11.1.1. El Problema del Saco de Palabras

En una arquitectura recurrente tradicional (RNN/LSTM), el tiempo y el orden están implícitos en la naturaleza secuencial del cómputo: el paso t no puede calcularse sin conocer el estado oculto ht−1.

Sin embargo, el motor central del Transformer, el Scaled Dot-Product Self-Attention, calcula la atención entre todos los pares de tokens en paralelo mediante operaciones matriciales:

Attention(Q,K,V)=softmax(QKTdk)V

Si permutamos el orden de las palabras de la secuencia de entrada mediante una matriz de permutación P, las matrices de Queries Q′=PQ y Keys K′=PK producen:

Q′K′T=(PQ)(PK)T=PQKTPT

Sin posiciones ni máscara dependiente del orden, la atención por filas verifica SA(PX)=PSA(X). Al permutar los tokens se permutan las filas de salida: es equivariancia, no invariancia. Una agregación simétrica posterior puede producir invariancia. La propiedad no se aplica sin cambios a una máscara causal fija.

Self-attention sin información posicional y sin máscara de orden es equivariante a permutaciones. Los vectores por token cambian de lugar con la entrada. Incorporar posiciones permite distinguir órdenes; una máscara causal también introduce estructura de orden.

11.2. Decisión Arquitectónica: Suma vs. Concatenación

11.2.1. ¿Por qué sumar Etok+PE?

La suma mantiene dmodel constante y permite usar las mismas dimensiones en las capas posteriores. Concatenar también es posible, pero cambia el ancho salvo que se añada una proyección. La suma no es invertible en general y no garantiza separar perfectamente contenido y posición. Los parámetros se aprenden con esa representación conjunta; no se presupone ortogonalidad entre ambos componentes.

11.3. Formulación Matemática de la Codificación Sinusoidal

11.3.1. Las ecuaciones sinusoidales

PEpos,2i=sin(pos/100002i/d),PEpos,2i+1=cos(pos/100002i/d).

pos es el índice del token e i el índice del par seno–coseno. La base 10000 controla el rango de frecuencias: λi=2π100002i/d, no una longitud máxima exactamente igual a 10000. Seno y coseno están intercalados por dimensiones en esta convención.

11.3.1.1. Propiedad de desplazamiento lineal

Cada par seno–coseno admite una transformación lineal para un desplazamiento fijo k:

[sin((pos+k)ωi)cos((pos+k)ωi)]=[cos(kωi)sin(kωi)−sin(kωi)cos(kωi)][sin(posωi)cos(posωi)].

Esto facilita representar desplazamientos, pero no obliga al producto punto de consultas y claves aprendidas a depender solo de la distancia relativa. RoPE impone esa estructura de manera explícita en sus rotaciones.

Presevando la Señal: Conexiones Residuales

11.3.1.2. Ejemplo Numérico

Para entender cómo se distribuyen las funciones trigonométricas en las dimensiones del vector, conviene analizar el rol exacto de los índices i, 2i y 2i+1, y luego desarrollar el cálculo numérico completo con dmodel=6

1. El Significado de i, 2i y 2i+1

Un vector de embedding de tamaño dmodel=6 tiene 6 componentes escalares indexados del 0 al 5:

𝐏pos=[p0,p1,p2,p3,p4,p5]

El algoritmo de Vaswani et al. no asigna una frecuencia distinta a cada una de las 6 dimensiones por separado. En su lugar, las agrupa en parejas (un par seno-coseno por cada frecuencia angular ωi) para formar planos bidimensionales de rotación:

  • i (Índice de la frecuencia o pareja): Recorre las parejas de dimensiones. Como cada pareja consume 2 posiciones del vector, i va desde 0 hasta dmodel2−1. Con dmodel=6:

    i∈{0,1,2}(exactamente 62=3 parejas)

  • 2i (Dimensión par): Selecciona el índice par del vector donde se evalúa la función seno.

  • 2i+1 (Dimensión impar): Selecciona el índice impar consecutivo donde se evalúa la función coseno con la misma frecuencia que su dimensión par compañera.

Las 3 parejas (i=0,1,2) cubren los 6 índices del vector: {0,1,2,3,4,5}.

2. Cálculo de los Denominadores (Escalas de Longitud de Onda)

La fórmula oficial define el divisor de cada frecuencia con la base escalar n=10000:

denominadori=n2idmodel=100002i6

Calculamos el divisor para cada valor de i:

  • Para i=0:

    denominador0=1000006=100000=1.0

  • Para i=1:

    denominador1=1000026=1000013=100003≈21.5443

  • Para i=2:

    denominador2=1000046=1000023=(1000013)2=(21.5443)2≈464.1589

A medida que i crece, el divisor se hace más grande, lo que genera frecuencias más lentas para capturar distancias más amplias en el texto.

3. Cálculo de Todos los Componentes para pos=1

Tomemos el token en la posición pos=1 (por ejemplo, la palabra "perro" en "el perro corre..."). Evaluamos cada índice j∈{0,1,2,3,4,5} en radianes:

  • Pareja i=0 (Índices 0 y 1):

    • Dimensión 0 (2i=0, par →sin):

      PE(1,0)=sin(posdenominador0)=sin(11.0)=sin(1 rad)≈0.8415

    • Dimensión 1 (2i+1=1, impar →cos):

      PE(1,1)=cos(posdenominador0)=cos(11.0)=cos(1 rad)≈0.5403

  • Pareja i=1 (Índices 2 y 3):

    • Ángulo: θ1=121.5443≈0.046416 rad

    • Dimensión 2 (2i=2, par →sin):

      PE(1,2)=sin(121.5443)=sin(0.046416 rad)≈0.0464

    • Dimensión 3 (2i+1=3, impar →cos):

      PE(1,3)=cos(121.5443)=cos(0.046416 rad)≈0.9989

  • Pareja i=2 (Índices 4 y 5):

    • Ángulo: θ2=1464.1589≈0.002154 rad

    • Dimensión 4 (2i=4, par →sin):

      PE(1,4)=sin(1464.1589)=sin(0.002154 rad)≈0.0022

    • Dimensión 5 (2i+1=5, impar →cos):

      PE(1,5)=cos(1464.1589)=cos(0.002154 rad)≈1.0000

  • Vector Posicional Resultante:

PE(1)=[0.8415,0.5403,0.0464,0.9989,0.0022,1.0000]

4. Comparación con pos=0

Para comprobar la consistencia matemática, si evaluamos la primera palabra de la secuencia (pos=0, como "el"):

  • PE(0,0)=sin(0/1)=0.0

  • PE(0,1)=cos(0/1)=1.0

  • PE(0,2)=sin(0/21.5443)=0.0

  • PE(0,3)=cos(0/21.5443)=1.0

  • PE(0,4)=sin(0/464.1589)=0.0

  • PE(0,5)=cos(0/464.1589)=1.0

PE(0)=[0.0,1.0,0.0,1.0,0.0,1.0]

La matriz de Positional Encoding 𝐏∈ℝseq\_len×dmodel tiene una estructura bidimensional fija:

  • Filas: Representan el índice temporal de cada palabra o token (pos=0,1,…,T−1).

  • Columnas: Representan las dimensiones del espacio de embedding (j=0,1,…,d−1).

                Dim 0        Dim 1        Dim 2        Dim 3        Dim 4        Dim 5
              (seno, i=0)  (cos, i=0)   (seno, i=1)  (cos, i=1)   (seno, i=2)  (cos, i=2)
            ┌                                                                             ┐
pos = 0     │      0           1            0           1            0           1        │  <- Vector PE(0)
pos = 1     │   0.8415      0.5403       0.0464      0.9989       0.0022       1.0000     │  <- Vector PE(1)
pos = 2     │   0.9093     -0.4161       0.0927      0.9957       0.0043       1.0000     │  <- Vector PE(2)
            └                                                                             ┘

Al alimentar el Transformer, el recorrido es fila por fila. Cada token de entrada tiene su propio vector semántico que necesita sumarse con el vector de su posición exacta:

𝐱final=𝐱token[pos,:]+𝐏[pos,:]

El modelo toma la fila completa pos (un vector de 6 números) y se la suma a la fila pos de la matriz de embeddings.

def build_pe_matrix(seq_len, d_model, n=10000.0):
    pe = np.zeros((seq_len, d_model), dtype=np.float32)
    for pos in range(seq_len):
        for i in range(d_model // 2):
            denom = np.power(n, (2 * i) / d_model)
            pe[pos, 2 * i]     = np.sin(pos / denom)
            pe[pos, 2 * i + 1] = np.cos(pos / denom)
    return pe

PE_matrix = build_pe_matrix(seq_len, embedding_dim)

12.1. La Filosofía Autorregresiva

  • Transformer Original (Vaswani et al., 2017): Concebido para traducción automática mediante una estructura Encoder-Decoder, donde el codificador procesa la secuencia de entrada bidireccionalmente y el decodificador genera la salida paso a paso.

  • BERT (Encoder-Only): Utiliza únicamente el codificador para aprender representaciones bidireccionales mediante Masked Language Modeling (MLM). Excelente para extracción de características, pero no diseñado para generación autoregresiva token a token.

  • GPT (Decoder-Only): Elimina el codificador y la atención cruzada (Cross-Attention), empleando exclusivamente una pila de bloques decodificadores causales. Su única tarea es predecir el siguiente token dada la historia pasada.

13.1.2.2. Términos cruzados en la autoatención con posiciones aditivas

Con codificación aditiva, la primera capa puede calcular Q y K a partir de embeddings más posición. Las capas siguientes reciben representaciones contextuales, no de nuevo el embedding original. RoPE rota las proyecciones Q y K en las capas de atención que lo incorporan.

Referencia: Su et al. · RoFormer

1. Deducción Matemática
A. Formulación del Producto Punto y Transposición

Por la propiedad distributiva de la multiplicación matriz-vector:

qm=xmWQ+pmWQ

kn=xnWK+pnWK

La afinidad de atención ⟨qm,kn⟩ se calcula como el producto matricial entre el vector fila qm y el vector columna kn⊤:

⟨qm,kn⟩=qmkn⊤=(xmWQ+pmWQ)(xnWK+pnWK)⊤

Aplicando la regla de transposición de una suma ((A+B)⊤=A⊤+B⊤) y de un producto matricial ((AB)⊤=B⊤A⊤):

(xnWK+pnWK)⊤=(xnWK)⊤+(pnWK)⊤=WK⊤xn⊤+WK⊤pn⊤

Sustituyendo en la expresión:

⟨qm,kn⟩=(xmWQ+pmWQ)(WK⊤xn⊤+WK⊤pn⊤)

B. Expansión distributiva (4 combinaciones posibles)

Al multiplicar algebraicamente los dos binomios término a término (propiedad distributiva completa (A+B)(C+D)=AC+AD+BC+BD):

  1. Primer término (A·C):

    (xmWQ)(WK⊤xn⊤)=xmWQWK⊤xn⊤

  2. Segundo término (A·D):

    (xmWQ)(WK⊤pn⊤)=xmWQWK⊤pn⊤

  3. Tercer término (B·C):

    (pmWQ)(WK⊤xn⊤)=pmWQWK⊤xn⊤

  4. Cuarto término (B·D):

    (pmWQ)(WK⊤pn⊤)=pmWQWK⊤pn⊤

Sumando los cuatro resultados se obtiene la expresión final:

⟨qm,kn⟩=xmWQWK⊤xn⊤⏟1. Semántica - Semántica+xmWQWK⊤pn⊤⏟2. Contenido - Posición+pmWQWK⊤xn⊤⏟3. Posición - Contenido+pmWQWK⊤pn⊤⏟4. Posición - Posición

Al calcular el producto punto de atención ⟨qm,kn⟩, la expresión se expande algebraicamente en cuatro sumandos:

⟨qm,kn⟩=xmWQWK⊤xn⊤⏟1. Semántica - Semántica+xmWQWK⊤pn⊤⏟2. Contenido - Posición+pmWQWK⊤xn⊤⏟3. Posición - Contenido+pmWQWK⊤pn⊤⏟4. Posición - Posición

2. Significado de los Términos

La expansión del producto de atención con posiciones aditivas contiene cuatro contribuciones:

(xm+pm)WQWK⊤(xn+pn)⊤.

Al distribuir aparecen contenido–contenido, contenido–posición, posición–contenido y posición–posición. Los términos cruzados no son necesariamente ruido: sus pesos se aprenden y pueden ayudar a utilizar el orden. Esta identidad no prueba que el modelo pierda significado o desperdicie capacidad.

Cualquier vector bidimensional [x0,x1]⊤∈ℝ2 equivale a un número complejo z=x0+ix1. Aplicando la fórmula de Euler, se escribe en forma polar:

z=reiϕ

  • r=x02+x12: La norma euclidiana del vector.

  • ϕ=arctan2(x1,x0): El ángulo que forma el vector con el eje real.

  • i: La unidad imaginaria (i2=−1).

  • eiϕ: Vector unitario sobre el círculo trigonométrico.

  • ¿Por qué en el plano complejo?: Multiplicar en ℂ separa de forma natural la longitud y la dirección: los radios se multiplican y los ángulos se suman.

Paso 3.1. Cálculo del Conjugado complejo de k~n

El conjugado de un número complejo invierte el signo de su parte imaginaria, lo que en forma polar equivale a negar el exponente:

k~n*=(rkei(ϕk+nθ))*=rke−i(ϕk+nθ)

Paso 3.2. Multiplicación de términos

q~m·k~n*=(rqei(ϕq+mθ))·(rke−i(ϕk+nθ))

Multiplicando los radios y sumando los exponentes algebraicamente:

q~m·k~n*=rqrkei((ϕq+mθ)−(ϕk+nθ))

Agrupando los términos por significado:

q~m·k~n*=rqrkei((ϕq−ϕk)+(m−n)θ)

Paso 3.3. Extracción de la parte real

Con vectores columna, (Rmq)⊤Rnk=q⊤Rn−mk. El factor rotatorio depende de n−m; los vectores q y k pueden contener información contextual y posicional procedente de otras capas. La identidad no elimina toda dependencia absoluta de un modelo completo.

13.3.2. La Separación Geométrica (Geometric Split)

En la formulación habitual, RoPE aplica rotaciones a parejas de coordenadas de Q y K proyectadas. Si q~m=Rmqm, la rotación conserva la norma porque Rm es ortogonal.

Eso no separa «qué palabra es» en la longitud y «dónde está» en el ángulo: el contenido de un vector está distribuido entre sus coordenadas. La posición modifica la fase de cada pareja y entra en el producto de atención mediante diferencias de posición. Los valores V no se rotan en esta formulación.

import torch
import numpy as np

# 1. Definición del vector de entrada y metadatos del problema
d_model = 4
m_pos = 2
x = torch.tensor([1.0, 0.5, 0.8, 0.3], dtype=torch.float32)

print("=== ENTRADA ORIGINAL ===")
print(f"Vector x: {x.tolist()} | Posición m: {m_pos} | Dimensión d: {d_model}\n")

# ------------------------------------------------------------------------------
# MÉTODO A: ENFOQUE MATRICIAL DIDÁCTICO (Subespacio por Subespacio)
# ------------------------------------------------------------------------------
# Cálculo de frecuencias inversas theta_i = 10000^(-2i / d)
i_indices = torch.arange(0, d_model // 2, dtype=torch.float32)
thetas = 1.0 / (10000.0 ** ((2.0 * i_indices) / d_model))

# Ángulos finales: alpha_i = m * theta_i
alphas = m_pos * thetas

# Construcción de matrices ortogonales 2D
R0 = torch.tensor([
    [torch.cos(alphas[0]), -torch.sin(alphas[0])],
    [torch.sin(alphas[0]),  torch.cos(alphas[0])]
])

R1 = torch.tensor([
    [torch.cos(alphas[1]), -torch.sin(alphas[1])],
    [torch.sin(alphas[1]),  torch.cos(alphas[1])]
])

# Rotación independiente por pares
x_pair0 = x[0:2]
x_pair1 = x[2:4]

x_rot_pair0 = R0 @ x_pair0
x_rot_pair1 = R1 @ x_pair1
x_rotated_matrix = torch.cat([x_rot_pair0, x_rot_pair1])

# ------------------------------------------------------------------------------
# MÉTODO B: ENFOQUE VECTORIZADO DE PRODUCCIÓN (Hadamard + rotate_half)
# ------------------------------------------------------------------------------
def rotate_half(tensor: torch.Tensor) -> torch.Tensor:
    """Intercala y niega elementos para simular la rotación compleja [-x1, x0, -x3, x2]."""
    x_pairs = tensor.view(-1, 2)
    rotated = torch.stack([-x_pairs[:, 1], x_pairs[:, 0]], dim=-1)
    return rotated.view_as(tensor)

# Duplicar frecuencias por parejas para broadcasting: [theta0, theta0, theta1, theta1]
freqs_expanded = alphas.repeat_interleave(2)
cos_cached = torch.cos(freqs_expanded)
sin_cached = torch.sin(freqs_expanded)

# Formulación de Su: x' = x * cos + rotate_half(x) * sin
x_rotated_vectorized = (x * cos_cached) + (rotate_half(x) * sin_cached)

# ------------------------------------------------------------------------------
# COMPROBACIÓN DE RESULTADOS Y PRESERVACIÓN DE NORMA
# ------------------------------------------------------------------------------
print("=== RESULTADOS DEL CÁLCULO NUMÉRICO ===")
print(f"Frecuencia Par 0 (i=0): theta_0 = {thetas[0].item():.4f} -> Ángulo: {alphas[0].item():.4f} rad ({np.degrees(alphas[0].item()):.2f}°)")
print(f"Frecuencia Par 1 (i=1): theta_1 = {thetas[1].item():.4f} -> Ángulo: {alphas[1].item():.4f} rad ({np.degrees(alphas[1].item()):.2f}°)")
print(f"\nVector Rotado (Método Matricial)  : {x_rotated_matrix.tolist()}")
print(f"Vector Rotado (Método Vectorizado): {x_rotated_vectorized.tolist()}")

# Validación de isonorma
norm_p0_orig = torch.norm(x_pair0).item()
norm_p0_rot  = torch.norm(x_rot_pair0).item()
norm_p1_orig = torch.norm(x_pair1).item()
norm_p1_rot  = torch.norm(x_rot_pair1).item()

print("\n=== COMPROBACIÓN DE ISONORMA (Norma Euclidiana) ===")
print(f"Par 0: ||x_orig|| = {norm_p0_orig:.6f} | ||x_rot|| = {norm_p0_rot:.6f} | Diferencia = {abs(norm_p0_orig - norm_p0_rot):.2e}")
print(f"Par 1: ||x_orig|| = {norm_p1_orig:.6f} | ||x_rot|| = {norm_p1_rot:.6f} | Diferencia = {abs(norm_p1_orig - norm_p1_rot):.2e}")

def update3d(frame):
  m_curr = m_steps_3d[frame]
  m_history = m_steps_3d[: frame + 1]

  # Trayectoria completa recorrida hasta el fotograma actual
  a0_hist = m_history * th0_val
  a1_hist = m_history * th1_val

  x0_traj = x0_base[0] * np.cos(a0_hist) - x0_base[1] * np.sin(a0_hist)
  y0_traj = x0_base[0] * np.sin(a0_hist) + x0_base[1] * np.cos(a0_hist)

  x1_traj = x1_base[0] * np.cos(a1_hist) - x1_base[1] * np.sin(a1_hist)
  y1_traj = x1_base[0] * np.sin(a1_hist) + x1_base[1] * np.cos(a1_hist)

  # Actualizar líneas de hélice
  helix_line0.set_data(x0_traj, y0_traj)
  helix_line0.set_3d_properties(m_history)

  helix_line1.set_data(x1_traj, y1_traj)
  helix_line1.set_3d_properties(m_history)

  # Posición del vector instantáneo actual
  cur_x0, cur_y0 = x0_traj[-1], y0_traj[-1]
  cur_x1, cur_y1 = x1_traj[-1], y1_traj[-1]

  # Actualizar vector radial desde el eje Z (0, 0, m) hasta la superficie
  rad_vec0.set_data([0, cur_x0], [0, cur_y0])
  rad_vec0.set_3d_properties([m_curr, m_curr])

  rad_vec1.set_data([0, cur_x1], [0, cur_y1])
  rad_vec1.set_3d_properties([m_curr, m_curr])

  # Actualizar puntos de la punta
  tip3d_0._offsets3d = ([cur_x0], [cur_y0], [m_curr])
  tip3d_1._offsets3d = ([cur_x1], [cur_y1], [m_curr])

  # Marcar tokens discretos enteros superados
  integer_ms = np.arange(0, int(m_curr) + 1)
  if len(integer_ms) > 0:
    int_a0 = integer_ms * th0_val
    int_a1 = integer_ms * th1_val
    ix0 = x0_base[0] * np.cos(int_a0) - x0_base[1] * np.sin(int_a0)
    iy0 = x0_base[0] * np.sin(int_a0) + x0_base[1] * np.cos(int_a0)
    ix1 = x1_base[0] * np.cos(int_a1) - x1_base[1] * np.sin(int_a1)
    iy1 = x1_base[0] * np.sin(int_a1) + x1_base[1] * np.cos(int_a1)
    tokens_scat0._offsets3d = (ix0, iy0, integer_ms)
    tokens_scat1._offsets3d = (ix1, iy1, integer_ms)

  # Texto HUD
  highlight_m2 = ' ★ [COINCIDE CON CELDA 1]' if abs(m_curr - 2.0) < 0.15 else ''
  title3d_hud.set_text(
      f'CILINDRO DE CONFINAMIENTO 3D — POSICIÓN DEL TOKEN: m = {m_curr:.2f}{highlight_m2}'
  )

  return (
      helix_line0,
      helix_line1,
      tip3d_0,
      tip3d_1,
      rad_vec0,
      rad_vec1,
      tokens_scat0,
      tokens_scat1,
      title3d_hud,
  )
