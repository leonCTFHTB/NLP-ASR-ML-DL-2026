24. Introducción

24.1. ¿Qué son las Redes Convolucionales?

Las redes convolucionales (o CNN, por Convolutional Neural Networks) son un tipo especial de red neuronal diseñada para procesar imágenes y videos. Su diferencia principal con las redes neuronales tradicionales es que utilizan una operación llamada convolución, la cual permite extraer automáticamente características importantes de las imágenes (bordes, texturas, formas, etc.)

24.1.1. Componentes Básicos

En las siguientes secciones se describen brevemente los componentes básicos de una red convolucional.

24.1.1.1. Filtros o Kernels

Un filtro es una pequeña matriz de números que se aplica sobre distintas partes de la imagen.

Al "deslizar" este filtro (convolución) sobre la imagen, se obtiene una nueva imagen transformada que resalta ciertas características.

Por ejemplo:

  • Un filtro puede detectar bordes horizontales.

  • Otro puede detectar bordes verticales o esquinas.

Cada filtro "aprende" a detectar una característica distinta durante el entrenamiento.

24.1.1.2. Mapa de Características (Feature Map)

El resultado de aplicar un filtro a una imagen se llama mapa de características. Cada mapa muestra dónde y cuán fuerte aparece una característica específica (como una rueda, una cara, o una línea, etc.).

Cuando se usan varios filtros, cada uno genera su propio mapa, y todos juntos forman un tensor tridimensional que describe la imagen desde distintos aspectos (en el caso en el que se esté trabajando con 3 dimensiones).

24.1.1.3. Padding

El padding consite en agregar bordes de cero alrededor de la imagen antes de aplicar la convolución (kernel).

Su objetivo es mantener el tamaño original de la imagen en la salida, evitando que se reduzca tras cada operación.

24.1.1.4. Max Pooling

El max pooling se utiliza para reducir el tamaño de las imágenes intermedias sin perder la información esencial.

Se divide la imagen en pequeñas regiones (por ej., 2x2 píxeles) y se toma el valor máximo de cada región.

Esto ayuda a:

  • Disminuir el costo computacional.

  • Resumir la información más relevante.

  • Aumentar la robustez del modelo ante pequeños cambios en la imagen.

24.1.1.5. Shapes (Dimensiones)

En redes convolucionales, cada imagen, filtro y mapa de características se representa como un tensor (una matriz de varias dimensiones).

El shape indica el tamaño de ese tensor, por ejemplo:

    (batch_size, height, width, channels)

Controlar los shapes es fundamental para asegurarse de que todas las capas de la red se conecten correctamente.

24.1.1.6. Resumen General

Concepto Función Principal
Convolución Extrae características visuales de la imagen.
Filtro / Kernel Define qué característica detectar (bordes, texturas, etc.).
Mapa de características Resultado de aplicar un filtro; representa patrones detectados.
Padding Mantiene el tamaño de la imagen tras la convolución.
Stride Controla el desplazamiento del filtro.

24.3.2.2. El filtro: una "linterna" que recorre la imagen

Podemos imageinar una capa de convolución como si tuvieramos una linerna que ilumina pequeñas zonas de la imagen.

Luego, supongamos que esa "linterna" (kernel) cubre un área de 5×5 píxeles.

  • La linterna se moverá por toda la imagen, iluminando una región diferente en cada paso.

    • El área que ilumni se llama campo receptivo.

Luego, mediante la herramienta cnn-explainer, podemos ver, como por cada canal RGB se aplica un filtro de 3×3 que aprende diferentes patrones por canal.

24.3.2.3. Capa Convolucional con un Solo Filtro

Para un mayor entendimiento, veamos un ejemplo más detallado. Supongamos que la imagen de entrada tiene un tamaño de (224×224×3). El tamaño espacial de un filtro es una elección de diseño, pero tiene que tener una profundiad de tres para coincidir con la profundidad de la imagen de entrada. En este caso, supongamos que usamos un único filtro de tamaño (3×3×3).

  • Estructura Interna de un Filtro Convolucional

Supongamos que tenemos un filtro con tres núcleos (kernels), uno por cada canal de color RGB (Rojo, Verde y Azul).

Cada kernel tiene tamaño de 3×3×1, lo que equivale a 9 parámetros entrenables. Como el filtro tiene 3 canalaes, el total de parámetros es:

3×3×3&=27&pesos entrenables

A esto se le suma un término de sesgo (Bias), dando un total de:

27+1&=28&pesos entrenables

  • Convolución por Canal y Combinación

Cuando aplicamos este filtro 3D (3×3×3) sobre una imagen con 3 canales (RGB):

  1. La convolución se realiza por separado en cada canal (R,G,B).

  2. Los resultados de los tres canales se combinan mediante una suma ponderada (sumando los valores resultantes de cada canal).

  3. Luego, se agrega el término de sesgo (bias).

  4. Finalmente, se aplica una función de activación (como ReLU, por ejemplo) para producir un único valor de salida.

Ese valor corresponde a una posición dentro del mapa de activación (feature map) generado por este filtro.

  • Profundidad de la Salida

Como en este ejemplo usamos solo un filtro, la salida tiene profundidad 1 - es decir, se genera un solo mapa de activación (una "imagen" en escala de grises que respresenta las activaciones del filtro).

  • Relación entre Canales, Filtros y Mapas de Activación

El número de canales de un filtro debe coincidir con el número de canales de la entrada. Por ejemplo, una entrada RGB (3 canales), entonces los filtros deben tener 3 canales.

Luego, el número de filtros en una capa convolucional determina cuántos mapas de activación se producirán.

  • Ejemplo Práctico

Supongamos que tenemos una capa convolucional con 32 filtros (32×32×3=3072):

  • Cada filtro genera su propio mapa de activación.

  • Por lo tanto, la salida de la capa tendrá una profundiad de 32 canales (uno por filtro).

  • Si la siguiente capa convolucional usa esa salida como entrada, cada uno de esos filtros deberá tener también 32 canales, para que la operación de convolución sea válida.

  • Supongamos que nuestro kernel es de 5×5×3=75.

    • El tamaño de la salida está dado por el tamaño de la matriz de entrada (o la imagen) nh×nw menos el tamño del kernel de convolución kh×kw, es decir:

    (nh−kh+1)×(nw−kw+1).

    • En nuestro caso, será:

    (32−5+1)×(32−5+1)=(28×28)=784.

24.3.2.4. Capa Convolucional con Dos Filtros

En el ejemplo anterior, la entrada tenía una profundidad de 3, lo que significa que el tensor de entrada posee 3 canales.

Importante: esto no siempre significa canales de colores (RGB); puede representar salida de una capa anterior de en la red.

Por tanto, cuando hablamos de entrada, nos referimos a la entrada de esta capa convolucional, no necesariamente a la entrada original del modelo.

Caso con Dos Filtros F1 y F2

Supognamos ahora que decidimos usar dos filtros en esta capa convolucional. Dado que la entrada tiene profundidad 3, cada filtro también debe tener profundidad 3 para que la operación de convolución sea válida.

  • Cálculo de parámetros:

    • Cada filtro contiene:

      • 3 kernels de tamaño 3××3×1=9 parámetros cada uno.

      • Es decir, 3×9=27 pesos entrenables por filtro.

    • Como tenemos 2 filtros, el total de pesos es:

      2×27&=54&pesos entrenables

    • A esto se suman 2 términos de sesgo (uno por cada filtro):

      54+2&=56&parámetros entrenables en total.

  • Resultado de la operación

    • Cada filtro produce su propio mapa de activación:

      • El Filtro 1 (F1) genera un mapa de activación 1.

      • El Filtro 2 (F2) genera un mapa de activación 2.

    La salida final de esta capa convolucional es entonces un tensor con profundidad 2, que contiene ambos mapas apilados.

24.3.2.5. Aprendizaje de Filtros Para Detectar Estructuras

Podemos pensar en cada filtro como una fuente que alberga nuevo conocimiento de algo especial y único sobre los datos de entrada. Estos pesos (números) se aprenden durante el proceso de entrenamiento. Los canales individuales en los mapas de activación en cualquier punto de la red representan características extraídas de la imagen de entrada (tensor de entrada, ya que no necesariamente tiene que ser una imagen)

En la imagen de arriba, tenemos una capa convolucional con tres filtros. Cada filtro aprende a detectar diferentes elementos estructurales (es decir, líneas horizontales, líneas verticales y líneas diagonales). Para ser más precisos, estas "líneas" representan estructuras de bordes en una imagen. En los mapas de activación de salida, enfatizamos las neuronas altamente activadas asociadas con cada filtro.

24.3.3. Capa ReLU

ReLU realiza una operación por elemento y establece todos los píxeles negativos en 0. Introduce una no linealidad a la red y la salida generada es un mapa de características rectificado.

Recordemos que, la no linealidad es necesaria para producir límites de decisión no lineales, de modo que la salida no pueda escribirse como una combinación lineal de las entradas.

  • Si no existiera una función de activación no lineal, las arquitecturas CNN profundas se reducirían a una única capa convolucional equivalente, que no funcionaría tan bien.

ReLU(x)&=max(0,x)

Esta función de activación se aplica elemento por elemnto a cada valor del tensor de entrada.

  • Por ejemplo, si se aplica ReLU al valor 2.24, el resultado sería 2.24, ya que 2.24 es mayor que 0.

  • La función ReLU se realiza después de cada capa convolucional en la arquitectura de red descrita anteriormente.

24.3.4. Capa de Max Pooling

En las arquitecturas de redes neuronales convolucionales (CNN), es común que las dimensaiones espaciales de los datos (ancho y alto de los mapas de activación) se reduzcan periódicamente mediante capas de pooling.

  • Esta capas se intercalan después de varias capas convolucionales y cumplen un papel clave:

    • Resumir y condensar la información más importante de los mapas de activación, reduciendo su tamaño sin perder las características esenciales.

El pooling con reducción espacial disminuye el número de activaciones y el coste de las capas posteriores. Max pooling no tiene parámetros entrenables; tampoco cambia por sí solo el número de pesos de una convolución posterior con igual número de canales y tamaño de kernel. Sí puede reducir los de una capa densa que recibe el mapa aplanado.

Seleccionar máximos puede dar tolerancia local a pequeños desplazamientos, con pérdida de detalle. Reducir resolución no garantiza eliminar información irrelevante ni evitar el sobreajuste.

¿Qué es el Pooling y Cómo Funciona?

El Pooling es una técnica utilizada en redes convolucionales para reducir el tamaño de los mapas de activación.

  • Lo hace aplicando un filtro deslizante 2D (sliding filter) sobre la salida de las capas convolucionales.

  • Este filtro se mueve a través de la imagen o mapa de activación y resume la información más importante de cada región que cubre.

24.3.4.1. El Parámetro Stride

El desplazamiento del filtro está controlado por un parámetro llamado stride (paso).

  • El stride indica cuántos píxeles se mueve el filtro cada vez que se aplica.

  • Por ejemplo:

    • Si stride = 1, el filtro se mueve un píxel a la vez (salida más detallada).

    • Si stride = 2, el filtro se mueve de dos en dos (salida más pequeña).

24.3.4.2. Tipos de Pooling

Existen dos operaciones principales de pooling:

Tipo Operación Descripción
Max Pooling max() Toma el valor máximo de la región analizada. Es el método más común, ya que conserva la característica más destacada.
Average Pooling avg() Calcula el promedio de los valores dentro de la región. Suaviza las activaciones.

La operación Max-Pooling requiere seleccionar un tamaño de kernel y una longitud de paso durante el diseño de la arquitectura (stride). Una vez seleccionados, la operación desliza el núcleo según el stride sobre la entrada, seleccionando solo el valor más grande en cada segmento del kernel de la entrada para otener un valor para la salida.

24.3.7.2. Padding

El relleno (padding) suele ser necesario cuando el kernel se extiende más allá del mapa de activación.

  • El padding conserva los datos en los bordes de los mapas de activación, lo que mejora el rendimiento y ayuda a preservar el tamaño espacial de la entrada, lo que permite crear redes más profundas y de mayor rendimiento.

  • Existen muchas técnicas de padding, pero el enfoque más utilizado es el padding con ceros debido a su rendimiento, simplicidad y eficiencia computacional.

    La técnica consiste en añadir ceros simétricamente alrededor de los bordes de una entrada.

24.3.7.3. Stride

El stride indica cuántos píxeles (en el caso de una imagen) debe desplazarse el kernel cada vez.

  • A medida que se reduce el stride, se aprenden más características porque extraen más datos, lo que también da lugar a capas de salida más grandes.

  • A medida que se aumenta el stride, se produce una extracción de característica más limitada y unas dimensiones de capa de salida más pequeñas.

23.3.8. Clasificador VGG-16

Las capas totalmente conectadas (densas) en una arquitectura CNN transforman características en probabilidades de clase. En el caso de VGG-16, la salida del último bloque convolucional (Conv-5) es una serie de mapas de activación con forma (7x7x512). Para referencia, hemos indicado el número de canales en puntos clave de la arquitectura.

Antes de que los datos de la última capa convolucional en el extractor de características puedan fluir a través del clasificador, deben aplanarse a un vector unidimensional de longitud 25088 (). Después de aplanarlos, esta capa unidimensional se conecta completamente a la capa FC-6.

23.3.8.1. Capa de Normalización por Lote (Batch Normalization - Batch Norm)

Su objetivo principal es normalizar las activaciones intermedias (no sólo los datos de entrada) para mejorar la estabilidad numérica, acelerar la convergencia y reducir la sensibilidad del modelo a la inicialización de los pesos.

El internal covariate shift fue una motivación histórica de BatchNorm. No debe presentarse su eliminación como explicación definitiva de su eficacia. Santurkar et al. estudiaron cómo la normalización modifica y suaviza la optimización.

En la práctica puede mejorar la estabilidad y permitir tasas de aprendizaje distintas, pero sus efectos dependen de la arquitectura, el lote y la tarea. No elimina automáticamente los gradientes explosivos o desvanecientes.

Fuente de la revisión: Santurkar et al. (2018)

23.3.8.2. Funcionamiento Paso a Paso - Batch Norm

Supongamos que tenemos una capa convolucional que produce un conjunto de mapas de activación 𝐀∈ℝ(N×C×H×W), donde

  • N = tamaño del batch,

  • C = número de canales (filtros),

  • H×W = dimensiones espaciales del mapa de activación.

El proceso de Batch Normalization se realiza independientemente por canal, y consta de las siguientes etapas:

  1. Cálculo de la media por canal

    μc&=1N×H×W∑i=1N∑j=1H∑k=1WAi,c,j,k

    Esta media representa el valor promedio de las activaciones del canal c en todo el batch.

  2. Cálculo de la varianza por canal

    σc&=1N×H×W∑i=1N∑j=1H∑k=1W(Ai,c,j,k−μc)2

  3. Normalización: Cada activación se normaliza restando la media y dividiendo por la desviación estándar (más un pequeño término ϵ para evitar división por cero):

    𝐀^i,c,j,k&=𝐀i,c,j,k−μcσc2+ϵ

  4. Escalado y desplazamiento (parámetros entrenables): La normalización pura restringe las activaciones a activaciones con media 0 y varianza 1, pero esto puede limitar la capacidad expresiva de la red.

    • Por eso se introducen dos parámetros entrenables, uno de escalado (γ) y otro de desplazamiento (β):

      𝐘i,c,j,k&=γc·𝐀^i,c,j,k+βc

    Estos parámetros permiten que la red aprenda la distribución óptima de activaciones, si es que una normalización estricta no resulta ideal.

Fuente de la revisión: PyTorch: BatchNorm2d

23.3.8.3. Integración con Funciones de Activación ReLU

En este bloque se usa el orden Conv → BatchNorm → ReLU. BatchNorm y ReLU son capas distintas; otras arquitecturas eligen otros órdenes.

ReLU tiene derivada 1 para entradas positivas y 0 para negativas. No evita todos los problemas del gradiente: puede producir unidades inactivas, y BatchNorm no garantiza impedirlo.

Fuente de la revisión: PyTorch: BatchNorm2d

23.3.8.4. Fase de Inferencia

Con model.eval() y track_running_stats=True, BatchNorm utiliza la media y la varianza acumuladas durante entrenamiento. Así la normalización de una muestra no depende de las otras muestras del lote de evaluación.

Si track_running_stats=False, se utilizan estadísticas del lote también en evaluación. Cambiar de distribución de datos puede afectar al resultado en ambos casos; las estadísticas acumuladas no garantizan buena generalización.

Fuente de la revisión: PyTorch: BatchNorm2d

23.3.8.5. Efectos prácticos en el rendimiento y la generalización

Los beneficios más relevantes de Batch Normalization son:

Beneficio Descripción
Estabiliza el entrenamiento Reduce la variabilidad en las distribuciones internas de activaciones.
Acelera la convergencia Permite usar learning rates más grandes en determinadas configuraciones; se debe comprobar la estabilidad.
Regulariza el modelo Introduce ruido estocástico debido al cálculo batch-wise, actuando como regularizador implícito.
Puede regularizar Puede disminuir la dependencia de otras técnicas como dropout.

Fuente de la revisión: PyTorch: BatchNorm2d

    -------------------
    - Bloque 1: 2x Conv2D(3→32) + ReLU + MaxPooling(2×2)
    - Bloque 2: 2x Conv2D(32→64) + ReLU + MaxPooling(2×2)

    CNNModel: Implementación de una red neuronal convolucional profunda
    inspirada en la arquitectura VGG, diseñada para clasificación de imágenes
    de entrada 3x32x32 (por ejemplo, CIFAR-10).

    Estructura general:
    -------------------
    - Bloque 1: 2x Conv2D(3→32) + ReLU + MaxPooling(2×2)
    - Bloque 2: 2x Conv2D(32→64) + ReLU + MaxPooling(2×2)
    - Bloque 3: 2x Conv2D(64→64) + ReLU + MaxPooling(2×2)
    - Flatten + 2 capas lineales (512 unidades ocultas → 10 clases)

    Parámetros:
    -----------
    input_shape : tuple, opcional
        Forma del tensor de entrada. Por defecto (3, 32, 32).

    Ejemplo de uso:
    ---------------
    >>> model = CNNModel()
    >>> x = torch.randn(8, 3, 32, 32)
    >>> y = model(x)
    >>> print(y.shape)
    torch.Size([8, 10])
    """

    def __init__(self, input_shape=(3, 32, 32)):
        super(CNNModel, self).__init__()

        # Bloque convolucional 1
        # Dos convoluciones consecutivas con 32 filtros y activación ReLU.
        # Se aplica MaxPooling para reducir las dimensiones espaciales a la mitad.
        self.conv1 = nn.Sequential(
            nn.Conv2d(in_channels=3, out_channels=32, kernel_size=3, padding=1),  # → (32, 32, 32)

            nn.ReLU(inplace=True),
            nn.MaxPool2d(kernel_size=2, stride=2),                                # → (32, 16, 16)
        )

        # Bloque convolucional 2
        # Incrementa el número de canales a 64, preservando estructura espacial.
        self.conv2 = nn.Sequential(
            nn.Conv2d(in_channels=32, out_channels=64, kernel_size=3, padding=1), # → (64, 16, 16)
            nn.ReLU(inplace=True),
            nn.Conv2d(in_channels=64, out_channels=64, kernel_size=3, padding=1), # → (64, 16, 16)
            nn.ReLU(inplace=True),
            nn.MaxPool2d(kernel_size=2, stride=2),                                # → (64, 8, 8)
        )

        # Bloque convolucional 3
        # Mantiene 64 canales pero profundiza la abstracción de características.
        self.conv3 = nn.Sequential(
            nn.Conv2d(in_channels=64, out_channels=64, kernel_size=3, padding=1), # → (64, 8, 8)
            nn.ReLU(inplace=True),

            nn.ReLU(inplace=True),
            nn.MaxPool2d(kernel_size=2, stride=2),                                # → (64, 4, 4)
        )

        self.flatten = nn.Flatten()  # Convierte (64, 4, 4) → 1024

        # Capas totalmente conectadas
        self.fc1 = nn.Linear(64 * 4 * 4, 512)   # Primera capa densa
        self.fc2 = nn.Linear(512, 10)           # Capa de salida (10 clases)

    def forward(self, x):
        """
        Propagación hacia adelante (Forward Pass)
        -----------------------------------------
        x : torch.Tensor
            Tensor de entrada con forma (N, 3, 32, 32)
        return : torch.Tensor
            Tensor de salida con probabilidades normalizadas (N, 10)
        """
        # Primer bloque convolucional
        x = self.conv1(x)   # → (N, 32, 16, 16)

        # Segundo bloque convolucional
        x = self.conv2(x)   # → (N, 64, 8, 8)

        # Tercer bloque convolucional
        x = self.conv3(x)   # → (N, 64, 4, 4)

        # Aplanamiento para pasar a las capas densas
        x = self.flatten(x) # → (N, 1024)

        # Capa totalmente conectada + activación ReLU
        x = self.fc1(x)
        x = nn.ReLU(inplace=True)(x)

        # Capa de salida + Softmax para clasificación multiclase
        x = self.fc2(x)
        x = nn.Softmax(dim=1)(x)

        return x
