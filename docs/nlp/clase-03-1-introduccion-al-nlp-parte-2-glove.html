2. La geometría del lenguaje: anatomía de GloVe

GloVe significa Global Vectors for Word Representation. Aprende vectores de palabras ajustando una puntuación al logaritmo de sus coocurrencias.

Para comprenderlo, retomaremos Word2Vec y seguiremos una secuencia: ventanas de texto → conteos acumulados → relaciones entre probabilidades → función de pérdida → optimización. Ambos métodos aprenden a partir del corpus completo; difieren en cómo organizan la evidencia y en el objetivo que optimizan.

2.1. Comparativa de arquitecturas

  • CBOW: contexto → centro. Combina las representaciones de las palabras vecinas para predecir la palabra central. La palabra objetivo se excluye de la entrada.
  • Skip-gram: centro → contexto. Parte de la palabra central para aprender a predecir palabras que aparecen en su entorno.

En la oración «el gato duerme», con radio de contexto 1, Skip-gram aprende pares como (gato, el) y (gato, duerme). CBOW utiliza «el» y «duerme» para predecir «gato».

2.1.1. Objetivo predictivo y estadísticas globales

Word2Vec procesa ventanas locales repartidas por todo el corpus. La repetición de esas ventanas aporta evidencia estadística global, aunque no se almacene una matriz explícita de conteos.

El softmax completo exige normalizar sobre todo el vocabulario. Sin embargo, negative sampling y softmax jerárquico ofrecen alternativas más eficientes; por eso no corresponde afirmar que Word2Vec siempre compara cada ejemplo con todo el vocabulario.

GloVe agrega los eventos de contexto antes de optimizar. La diferencia útil es aprender desde ejemplos de predicción frente a ajustar estadísticas de coocurrencia agregadas. La velocidad depende del corpus, la ventana, la implementación y el costo de construir la matriz.

2.2. El surgimiento de GloVe y la matriz de coocurrencia

GloVe construye una matriz X recorriendo ventanas de contexto y acumulando sus contribuciones. Global se refiere a esa agregación a lo largo del corpus: no implica usar todo el documento como ventana.

Analogía: una libreta recibe una anotación por cada encuentro entre dos palabras. Antes de entrenar, esas anotaciones se consolidan en un archivo de frecuencias. El aprendizaje consulta ese archivo en lugar de volver a representar cada encuentro individual.

2.2.1. La estructura de la matriz X

Las filas representan palabras centrales y las columnas palabras de contexto:

  • xij: contribución acumulada del contexto j junto al centro i. Puede ser un conteo entero o una suma de pesos, por ejemplo 1/d según la distancia entre posiciones.
  • xi=∑k∈Vxik: total de eventos de contexto de la fila i. No es, en general, la cantidad de apariciones de la palabra central.
  • Para xi>0, pij=P(j∣i)=xij/xi es la distribución empírica del contexto de i.

Esta probabilidad describe los datos y las decisiones de preprocesamiento. No constituye una probabilidad universal del lenguaje ni es la salida directa del modelo final de GloVe.

2.2.2. La eficiencia computacional

Una matriz de 100000×100000 contiene 1010 posiciones. Por ello, una implementación a gran escala almacena sus entradas no nulas en una estructura dispersa.

Definimos Ω={(i,j):xij>0}. El objetivo se evalúa solamente en ese conjunto. El costo de una pasada de entrenamiento depende de |Ω| y de la dimensión de los vectores; también hay que considerar el preprocesamiento y el almacenamiento de X.

Primero se filtran los ceros y después se calcula el logaritmo. La expresión numérica 0 * log(0) puede producir NaN; definir h(0)=0 no vuelve segura esa operación.

En 2.3 usaremos una matriz densa únicamente porque el corpus didáctico es pequeño.

2.2.3. El significado en las proporciones y las palabras sonda

Un cociente de probabilidades permite preguntar qué contextos distinguen dos palabras centrales.

Comparemos ice (hielo) y steam (vapor). Para cada palabra sonda o contexto fijo k, calculamos:

Rk=P(k∣ice)P(k∣steam).

Un valor grande favorece a ice frente a steam para ese contexto; un valor pequeño favorece a steam. Un valor cercano a 1 indica que ese contexto discrimina poco entre los dos centros. El cociente se interpreta cuando el denominador es positivo; la intuición no requiere calcular cocientes para todos los ceros de X.

La comparación mantiene siempre el mismo contexto en numerador y denominador:

  • solid: aparece relativamente más con ice.
  • gas: aparece relativamente más con steam.
  • water: puede asociarse con ambos centros y diferenciarlos poco.
  • fashion: puede tener probabilidades pequeñas con ambos y también diferenciarlos poco.

Un cociente cercano a 1 no significa que las probabilidades sean pequeñas ni que una palabra sea irrelevante para cualquier tarea. Indica poca discriminación en esta comparación concreta.

2.2.4. Interpretación geométrica: aproximación de cocientes

Representemos los dos centros mediante vi y vj, y el contexto fijo mediante uk. Queremos relacionar una diferencia de vectores con un escalar observado:

F(vi−vj,uk)≈P(k∣i)P(k∣j).

El producto punto (vi−vj)⊤uk resume la diferencia frente al mismo contexto. En esta sección i,j identifican dos centros; k identifica el contexto sonda. En la función de pérdida volveremos a usar (i,j) para un par centro–contexto.

La identidad exponencial convierte una resta de escalares en un cociente positivo:

exp(a−b)=exp(a)exp(b).

Esto motiva usar exp((vi−vj)⊤uk) para describir relaciones de coocurrencia. Es una motivación para construir el modelo, no una afirmación de que cada exponencial sea una probabilidad normalizada.

Al incorporar los sesgos y los totales por fila del modelo final, la relación queda:

logP(k∣i)P(k∣j)≈(vi−vj)⊤uk+bi−bj−logxi+logxj.

El sesgo del contexto se cancela al mantener k fijo. Así se distinguen la identidad algebraica, la motivación inicial y el objetivo final con sesgos.

El producto punto satisface:

u⊤v=‖u‖‖v‖cosθ.

Combina normas y dirección. No mide únicamente paralelismo: un vector más largo puede producir un producto punto mayor sin cambiar el ángulo. El coseno normalizado elimina esa dependencia de las normas para vectores no nulos.

Restar dos productos punto compara puntuaciones aprendidas frente a un mismo contexto. La exponencial vuelve positivo el resultado, pero no lo restringe al intervalo [0,1].

2.2.4.1. Analogía

Imaginemos dos fichas —ice y steam— y una misma pregunta: «¿qué evidencia hay de aparecer con solid?». Cada ficha recibe una puntuación. La diferencia indica cuál recibe más; la exponencial traduce esa diferencia a una escala multiplicativa.

La pregunta debe ser la misma para ambas fichas. Comparar solid con gas dentro de ice responde otra pregunta y no reproduce el cociente anterior. La analogía tampoco supone imanes ni fuerzas físicas.

2.2.5. La ecuación principal: regresión logarítmica de coocurrencias

El modelo final asigna a un par observado (i,j) una puntuación:

y^ij=vi⊤uj+bi+cj≈logxij,(i,j)∈Ω.

Ahora i es el centro y j el contexto. Se trata de un modelo log-bilineal con sesgos: la parte vectorial es bilineal y el objetivo es el logaritmo del conteo. No es una regresión logística ni una distribución softmax.

La puntuación combina tres elementos:

  • Producto punto vi⊤uj: interacción de los vectores, dependiente de normas y dirección.
  • Sesgos bi,cj: escalares aprendidos para los roles de centro y contexto. Permiten representar parte de las diferencias de frecuencia sin obligar al producto punto a explicarlas por completo.
  • Objetivo logxij: dato fijo durante el ajuste. El logaritmo comprime el rango de los conteos.

En la figura, vi=(1,2) y uj=(0.2,0.4) dan un producto punto de 1. Con sesgos 0.4 y 0.6, la puntuación total es 2. Son números ilustrativos, no vectores entrenados.

2.2.6. Función de pérdida: mínimos cuadrados ponderados

Definimos el residual rij=y^ij−logxij. La pérdida es:

J=∑(i,j)∈Ωh(xij)(vi⊤uj+bi+cj−logxij)2.

Es una suma de errores cuadrados ponderados. Dividirla por una constante fija, como la cantidad de pares, conserva sus minimizadores pero cambia la escala de sus gradientes. Por precisión, no llamaremos «media» a una implementación que utiliza una suma.

GloVe ajusta logaritmos de conteos; Word2Vec utiliza objetivos predictivos con variantes eficientes. La comparación no exige que todos los modelos de Word2Vec calculen softmax completo.

La función de ponderación habitual es:

h(x)={(x/xmax)α,0<x<xmax,1,x≥xmax.

El artículo utiliza α=0.75 y xmax=100. En el corpus pequeño de 2.3 fijamos xmax=5 para visualizar el cambio de régimen.

  • Los pares raros reciben pesos menores que los pares con conteos más altos.
  • El peso llega a 1 y después no aumenta: se satura el peso, no el conteo ni el residual.
  • Los ceros se excluyen antes de evaluar log. Puede extenderse la definición con h(0)=0, pero eso no permite calcular numéricamente 0 * log(0).

La saturación no elimina stopwords ni garantiza un límite para el gradiente de cada par.

2.2.7. La dinámica del entrenamiento: una analogía de regulación

Pensemos en una perilla que regula una puntuación, con una marca objetivo en logxij. Si la predicción queda por debajo, el ajuste intenta aumentarla; si queda por encima, intenta reducirla.

rij=vi⊤uj+bi+cj−logxij.

La analogía se aplica al error de la puntuación. No describe un resorte físico entre dos puntos ni una pérdida basada en distancia euclídea. Además de los vectores, se actualizan los sesgos.

1. Predicción por debajo del objetivo: rij<0.

Para la contribución ℓij=h(xij)rij2 de un solo par, el descenso simple produce:

Δvi=−2ηh(xij)rijuj.

Con uj fijo y η>0, el coeficiente es positivo: el paso sigue la dirección +uj. El cambio de producto punto es −2ηh(xij)rij‖uj‖2≥0. Esto no equivale necesariamente a acercar dos extremos vectoriales en distancia euclídea.

2. Predicción por encima del objetivo: rij>0.

El mismo paso tiene dirección −uj y reduce el producto punto si uj permanece fijo y es no nulo.

El diagrama representa un paso de descenso simple para un par aislado. En entrenamiento se suman aportes de otros pares y también cambian los contextos y sesgos. AdaGrad reescala las coordenadas: no corresponde interpretar su actualización como un movimiento siempre paralelo a uj.

3. Residual cero. Si rij=0, ese par aporta gradiente cero. Otros pares pueden seguir modificando los mismos parámetros; no implica que todo el entrenamiento haya terminado.

4. Papel del peso. El factor h(xij) modula la contribución del par observado. Con el mismo residual y el mismo contexto, un peso menor reduce la magnitud de esa contribución.

En la figura, el factor escalar |2h(x)r| vale 0.8 para h=0.2,r=2, y 4 para h=1,r=2. Si el residual crece, el gradiente puede crecer aunque el peso esté saturado.

2.2.7.1. ¿Por qué se utiliza AdaGrad en GloVe?

Las frecuencias lingüísticas suelen ser muy desiguales: pocos términos concentran muchas apariciones y muchos términos aparecen poco. Esto produce historiales de gradientes diferentes para distintos parámetros.

AdaGrad acumula el cuadrado de los gradientes por coordenada y adapta la escala de las actualizaciones. Es una opción utilizada en el entrenamiento original de GloVe, no un requisito exclusivo del modelo. SGD tampoco es necesariamente inestable por usar una tasa constante: su comportamiento depende de esa tasa y del problema.

2.2.7.2. La actualización con AdaGrad

Para cada coordenada, sin decaimiento ni regularización:

Gt=Gt−1+gt⊙gt, θt+1=θt−ηgtGt+ϵ.

El producto ⊙, la raíz y la división operan por coordenada. Esta forma coloca ϵ fuera de la raíz, como la implementación de PyTorch usada en el ejemplo.

Una coordenada con mayor acumulado recibe una tasa efectiva menor. La frecuencia de una palabra influye en las oportunidades de actualización, pero el acumulado depende de los gradientes, no solo de contar apariciones. AdaGrad no crea evidencia para palabras ausentes ni garantiza un buen embedding con pocos datos.

2.2.7.3. Deducción y derivación matemática paso a paso

1. Definición de la función de pérdida global

J=∑(i,j)∈Ωh(xij)rij2,rij=vi⊤uj+bi+cj−logxij.

Símbolo Significado
V Vocabulario
Ω Pares con xij>0
i,j Índices del centro y del contexto
vi,uj∈Rd Vectores aprendidos en cada rol
bi,cj∈R Sesgos aprendidos
xij Coocurrencia acumulada, posiblemente ponderada
rij Residual de la puntuación respecto al objetivo
h(xij) Peso fijo del par durante la optimización
2. Derivación respecto al vector central vi

Fijamos el centro i. Se mantienen constantes los conteos, los pesos y los demás parámetros al tomar esta derivada parcial.

Paso 1: aislar los términos que dependen de vi

Los términos de otros centros no dependen de este vector. Para su derivada basta considerar:

Ji=∑j:xij>0h(xij)(vi⊤uj+bi+cj−logxij)2.

Paso 2: definir el residual escalar

rij=vi⊤uj+bi+cj−logxij.

Entonces Ji=∑j:xij>0h(xij)rij2. El residual es un escalar; vi y uj son vectores.

Paso 3: aplicar la regla de la cadena

∇viJi=∑j:xij>0h(xij)2rij∇virij.

El conteo no se aprende: por eso h(xij) y logxij permanecen constantes en esta derivada.

Paso 4: derivar el término interno

vi⊤uj=∑q=1dviqujq⟹∇vi(vi⊤uj)=uj.

Los sesgos bi,cj son parámetros separados de las componentes de vi. Sus derivadas respecto a este vector son cero; lo mismo ocurre con logxij. Por tanto:

∇virij=uj.

Paso 5: sustituir y obtener el gradiente

∇viJ=2∑j:xij>0h(xij)rijuj.

El resultado tiene d componentes, como el vector que se actualiza. Para los vectores de contexto, de manera análoga:

∇ujJ=2∑i:xij>0h(xij)rijvi.

3. Derivación de los sesgos escalares

Como ∂rij/∂bi=1:

∂J∂bi=2∑j:xij>0h(xij)rij.

Para el sesgo del contexto:

∂J∂cj=2∑i:xij>0h(xij)rij.

Los sesgos también participan en la corrección del residual. No todo el cambio necesario recae en los vectores.

2.2.7.4. Interpretación geométrica

Cada contribución al gradiente central combina un peso, un error con signo y un vector de contexto:

2h(xij)rijuj.

El gradiente global suma estas contribuciones. El descenso se mueve en sentido opuesto al gradiente; AdaGrad aplica además una escala por coordenada. Por eso el movimiento final puede diferir de la dirección de cualquier contexto aislado.

La interpretación correcta trata sobre ajustar puntuaciones. No garantiza agrupaciones semánticas, paralelismo ni distancias euclídeas concretas.

2.2.8. Simetría y representación dual

Con una ventana simétrica y pesos iguales hacia ambos lados, puede cumplirse xij=xji. Una ventana direccional no tiene esa garantía.

El modelo mantiene dos tablas de parámetros: W para centros y U para contextos. Una palabra puede aparecer en ambos roles y tiene una fila en cada tabla. Los roles separados también aparecen en variantes de Word2Vec.

Aunque X sea simétrica, la optimización no impone W=U ni obliga a que sus coordenadas coincidan. Una representación de salida habitual es:

ei=vi+ui.

Es una elección para combinar las dos representaciones aprendidas. No es un «colapso de simetría» obligatorio, no elimina la variación entre semillas y no garantiza evitar el sobreajuste. La calidad debe evaluarse en la tarea de interés.

2.3.2. Corpus y construcción de la matriz global X

  1. Se tokeniza cada oración y se asigna un índice a cada palabra.
  2. Se recorre una ventana con radio 2: hasta dos posiciones a cada lado.
  3. Cada vecino suma 1/d, donde d es su distancia al centro. Se excluye la misma posición y no se cruzan los límites de oración.
  4. Se extraen los pares con xij>0 antes de calcular sus logaritmos.

La matriz densa facilita inspeccionar este ejemplo. Para corpus grandes se reemplaza por acumulación y almacenamiento dispersos; no se reserva una matriz densa de tamaño |V|2.

Código Python · bloque 78
# =====================================================================
# 1. CORPUS Y CONSTRUCCIÓN DE LA MATRIZ DE CO-OCURRENCIA GLOBAL (X)
# =====================================================================
# Definimos un corpus de prueba con relaciones semánticas duales (Clima/Estados vs. Animales)
corpus = [
    "el hielo es agua solida y fria",
    "el vapor es agua en estado gaseoso y caliente",
    "el hielo y el vapor son estados del agua",
    "el gato es un animal domestico y peludo",
    "el perro es un animal domestico y leal",
    "el gato y el perro son animales peludos"
]

# Tokenización limpia y construcción del vocabulario
words = [w for sentence in corpus for w in sentence.lower().split()]
vocabulary = sorted(list(set(words)))
vocab_size = len(vocabulary)
word_to_idx = {w: i for i, w in enumerate(vocabulary)}
idx_to_word = {i: w for i, w in enumerate(vocabulary)}

print(f"Vocabulario generado ({vocab_size} palabras únicas): {vocabulary}\n")

# Construcción de la Matriz de Co-ocurrencia X mediante Ventana Deslizante
WINDOW_SIZE = 2
X_matrix = np.zeros((vocab_size, vocab_size), dtype=np.float32)

for sentence in corpus:
    tokens = [word_to_idx[w] for w in sentence.lower().split()]
    for center_i, center_idx in enumerate(tokens):
        start = max(0, center_i - WINDOW_SIZE)
        end = min(len(tokens), center_i + WINDOW_SIZE + 1)
        for context_i in range(start, end):
            if center_i != context_i:
                context_idx = tokens[context_i]
                # Ponderación basada en la distancia física dentro de la ventana: 1 / d
                distance = abs(center_i - context_i)
                X_matrix[center_idx, context_idx] += 1.0 / distance

# EXTRACCIÓN DE ENTRADAS NO NULAS (x_ij > 0):
# GloVe evalúa el objetivo solo para pares con conteo positivo.
i_indices, j_indices = np.nonzero(X_matrix)
x_values = X_matrix[i_indices, j_indices]

# Convertimos los datos precomputados a Tensores de PyTorch
i_tensor = torch.tensor(i_indices, dtype=torch.long)
j_tensor = torch.tensor(j_indices, dtype=torch.long)
x_tensor = torch.tensor(x_values, dtype=torch.float32)

print(f"Matriz X calculada. Total de pares no nulos a optimizar: {len(x_values)}")
print(x_values)

2.3.3. Arquitectura y función de ponderación

GloVeModel consulta cuatro tablas: vectores de centro y contexto con forma (|V|,d), y dos tablas de sesgos con forma (|V|,1).

Para N pares, forward devuelve N puntuaciones vi⊤uj+bi+cj. La operación squeeze(-1) elimina solo el eje del sesgo y conserva la dimensión del lote incluso para un único par.

glove_weight_func calcula h(x). La pérdida se construye en la siguiente celda y utiliza únicamente conteos positivos.

Código Python · bloque 82
# =====================================================================
# 2. DEFINICIÓN DE LA ARQUITECTURA Y PÉRDIDA DE GLOVE
# =====================================================================
class GloVeModel(nn.Module):
    """Aprende dos tablas de vectores y dos sesgos para pares centro-contexto.

    Args:
        vocab_size: Cantidad de palabras del vocabulario; debe ser positiva.
        embedding_dim: Dimensión positiva de los vectores; 2 permite dibujarlos.

    Notes:
        El modelo devuelve puntuaciones para ajustar logaritmos de conteos.
        No aplica softmax ni devuelve probabilidades normalizadas.
    """
    def __init__(self, vocab_size, embedding_dim=2):
        # Inicializar el módulo base y validar el tamaño de sus tablas.
        super(GloVeModel, self).__init__()
        if vocab_size < 1 or embedding_dim < 1:
            raise ValueError("vocab_size y embedding_dim deben ser positivos.")
        # Matriz de Vectores Centrales (v)
        self.center_embeddings = nn.Embedding(vocab_size, embedding_dim)
        # Matriz de Vectores de Contexto (u)
        self.context_embeddings = nn.Embedding(vocab_size, embedding_dim)

        # Sesgos escalares para absorber las frecuencias base independientes (b_i y c_j)
        self.center_biases = nn.Embedding(vocab_size, 1)
        self.context_biases = nn.Embedding(vocab_size, 1)

        # Inicialización uniforme de pesos para este ejemplo didáctico
        initrange = 0.5 / embedding_dim
        self.center_embeddings.weight.data.uniform_(-initrange, initrange)
        self.context_embeddings.weight.data.uniform_(-initrange, initrange)
        self.center_biases.weight.data.zero_()
        self.context_biases.weight.data.zero_()

    def forward(self, i_idx, j_idx):
        """Calcula una puntuación por par de índices.

        Args:
            i_idx: Tensor entero de centros, con forma (N,).
            j_idx: Tensor entero de contextos, con forma (N,).

        Returns:
            Tensor de forma (N,) con producto punto y ambos sesgos.
            Se conserva esa forma cuando N vale 1.
        """
        # Selección de vectores y sesgos para cada par (i, j)
        v_i = self.center_embeddings(i_idx)       # [N, dim]
        u_j = self.context_embeddings(j_idx)      # [N, dim]
        b_i = self.center_biases(i_idx).squeeze(-1)  # [N]
        c_j = self.context_biases(j_idx).squeeze(-1)  # [N]

        # Producto punto u_j^T * v_i
        dot_product = torch.sum(v_i * u_j, dim=-1)

        # Predicción geométrica log-bilineal: u_j^T * v_i + b_i + c_j
        prediction = dot_product + b_i + c_j
        return prediction

def glove_weight_func(x, x_max=10.0, alpha=0.75):
    """Pondera los conteos sin modificar el objetivo logarítmico.

    Args:
        x: Tensor de conteos no negativos. Para calcular log(x), filtrar x > 0.
        x_max: Umbral positivo a partir del cual el peso vale 1.
        alpha: Exponente positivo de la región inferior al umbral.

    Returns:
        Tensor de pesos con la misma forma que x y valores entre 0 y 1.

    Raises:
        ValueError: Si los hiperparámetros no son positivos o hay conteos negativos.
    """
    # Validar antes de elevar a una potencia fraccionaria.
    if x_max <= 0 or alpha <= 0 or torch.any(x < 0):
        raise ValueError("Se requieren x >= 0, x_max > 0 y alpha > 0.")
    weights = (x / x_max) ** alpha
    return torch.clamp(weights, max=1.0)

2.3.4. Entrenamiento con AdaGrad y combinación de representaciones

Cada época procesa todos los pares observados en un solo lote. Esta simplificación mantiene el objetivo de GloVe, aunque difiere de una implementación a gran escala que utiliza lotes o actualizaciones por par.

  1. Se calculan las puntuaciones y el objetivo logx.
  2. Se aplica h(x) y se suman los errores cuadrados ponderados.
  3. Se calculan gradientes y AdaGrad actualiza los parámetros.
  4. Se guarda W+U para observar la evolución; esa suma no se realimenta al modelo.

El historial registra la pérdida evaluada antes de cada actualización y los vectores después de ella. Es una convención de registro, no una igualdad temporal entre ambas mediciones.

Código Python · bloque 85
# =====================================================================
# 3. BUCLE DE ENTRENAMIENTO CON ADAGRAD Y COMBINACIÓN DE REPRESENTACIONES
# =====================================================================
EMBEDDING_DIM = 2  # 2D para visualización geométrica directa
EPOCHS = 200
LR = 0.05
X_MAX = 5.0        # Ajustado para nuestro corpus de prueba pequeño
ALPHA = 0.75

model = GloVeModel(vocab_size=vocab_size, embedding_dim=EMBEDDING_DIM)

# Se utiliza AdaGrad para adaptar la tasa de aprendizaje por parámetro (crucial para Zipf)
optimizer = optim.Adagrad(model.parameters(), lr=LR)

vector_history = []  # Para capturar la evolución de e_i = v_i + u_i
loss_history = []

print("Entrenando la red neuronal GloVe y calculando la trayectoria geométrica...")

for epoch in range(EPOCHS):
    optimizer.zero_grad()

    # 1. Forward Pass: Calcular predicciones sobre pares no nulos
    predictions = model(i_tensor, j_tensor)
    log_x = torch.log(x_tensor)  # Objetivo fijo: logaritmo del conteo positivo

    # 2. Ponderación h(x)
    weights = glove_weight_func(x_tensor, x_max=X_MAX, alpha=ALPHA)

    # 3. Función de Pérdida Suma de errores cuadrados ponderados: J = sum h(x_ij) * (pred - log(x_ij))^2
    loss = torch.sum(weights * ((predictions - log_x) ** 2))

    # 4. Retropropagación y actualización con AdaGrad
    loss.backward()
    optimizer.step()

    # 5. Representación combinada para visualización:
    # Sumamos las matrices centro (v) y contexto (u) para obtener la representación e_i = v_i + u_i
    v_all = model.center_embeddings.weight.detach().cpu().numpy()
    u_all = model.context_embeddings.weight.detach().cpu().numpy()
    final_representation = v_all + u_all

    # Guardamos en el historial para animación
    vector_history.append(final_representation.copy())
    loss_history.append(loss.item())

print("Entrenamiento finalizado. Construyendo el entorno visual Plotly...")
